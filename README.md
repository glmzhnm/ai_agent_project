# Ассистент дежурной смены

Мини-дашборд для команды поддержки хостинг-провайдера. Агент вставляет текст
проблемы из тикета, ассистент возвращает разбор: вероятная причина, порядок
проверки, команды для диагностики, уровень риска и признак эскалации.

## Запуск

Нужны Python 3.11 и Node 18.

### 1. Backend

```bash
cp .env.example .env          # и вписать ключ в .env
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

Проверка: `curl http://127.0.0.1:8000/api/health`

### 2. Frontend

```bash
cd frontend
npm install
npm run dev
```

Открыть http://localhost:5173

Vite проксирует `/api` на backend, поэтому ключ модели никогда не попадает в
браузер и CORS в разработке не мешает.

## Структура

```
backend/app
  main.py          маршруты, CORS, обработчик ошибок
  config.py        настройки из окружения
  schemas.py       контракты запроса и ответа
  prompts.py       системный промпт и три режима работы
  llm_client.py    вызов Anthropic или OpenAI, таймауты, ретраи
  errors.py        доменные ошибки с HTTP-кодами
  services/ask.py  сценарий: промпт, вызов, разбор JSON, деградация
frontend/src
  App.jsx          состояние экрана и связывание компонентов
  api/client.js    единственное место, где есть fetch
  hooks/useHistory.js  последние 5 запросов в localStorage
  lib/format.js    экспорт ответа в текст и копирование
  components/      QuestionForm, AnswerCard, HistoryList, ErrorBanner, StatusBar
```

## Принятые решения

**Специализация вместо второго ChatGPT.** Ассистент отвечает как инженер
поддержки хостинга: у него описана зона ответственности, порядок диагностики от
дешёвой проверки к дорогой, запрет выдумывать пути в панелях и правило помечать
любую изменяющую команду как высокий риск. Вопрос вне зоны ответственности он
помечает флагом, а не отвечает наугад.

**Структурированный ответ, а не строка.** Модель возвращает JSON по фиксированной
схеме: суть, шаги, команды, риск, эскалация, что уточнить, теги. Интерфейс
рисует из этого нормальный разбор, а не стену текста, и по каждому полю понятно,
чего не хватает в ответе модели.

**Три режима под реальный рабочий поток.** Один и тот же вопрос нужен в трёх
видах: для себя, в виде готового ответа клиенту и в виде сводки для эскалации.
Режим меняет системную инструкцию, схема ответа остаётся одна.

**Ошибки как часть сценария.** Нет ключа, таймаут, лимит запросов, битый JSON от
модели: на каждый случай свой понятный текст и кнопка повторить. Если модель
вернула не JSON, сервис пробует починить вторым вызовом и только потом
показывает упрощённый вид с честной пометкой. Сервис не падает ни в одном из
этих случаев.

**Backend как прокси.** Ключ живёт только на сервере. Плюс появляется место для
лимитов и логов, если сервис поедет дальше учебного задания.

## Что показать в видео

1. Здоровье сервиса в шапке, затем реальный вопрос в режиме "Для инженера".
2. Тот же вопрос в режиме "Ответ клиенту": меняется и тон, и состав ответа.
3. Вопрос вне зоны ответственности: срабатывает out_of_scope.
4. Опасный сценарий: модель ставит высокий риск и эскалацию.
5. История последних пяти запросов и возврат к старому ответу.
6. Ошибка: остановить backend и показать понятное сообщение вместо белого экрана.
7. Код: prompts.py и services/ask.py, разбор JSON с починкой и деградацией.
